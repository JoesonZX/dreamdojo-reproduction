## 第 0 部分:VLA 学习路径

**前置**:Transformer/注意力、模仿学习=行为克隆(BC)、扩散/流匹配基础。

**论文阅读顺序**(每篇抓一个核心概念):
1. **ACT / Diffusion Policy** → action chunking(一次预测一段动作)。
2. **RT-1 → RT-2** → 动作离散成 token、用 LLM 自回归预测;RT-2 引入 VLM 语义泛化。
3. **OpenVLA** → 标准 VLA 范式(ViT/SigLIP + LLM + 离散动作 token)。
4. **π0 → π0.5** → 流匹配"动作专家"连续生成动作。**这是理解 Fast-WAM 的直接前置。**

读到第 4 步即具备读 Fast-WAM 的全部背景。

## 第 1 部分:VLA 数据流与核心概念

### 1.1 VLA 数据流总览
VLA 本质是函数 `p(a_{1:H} | o, l)`:给定观测+指令,直接输出未来一段动作。

```
o 当前观测(多相机 RGB) ─→[视觉编码器 ViT/SigLIP]─→ 视觉token ┐
l 语言指令 ────────────→[tokenizer]──────────────→ 文本token ─┼─→[VLM主干 跨模态融合]
p 本体状态(可选) ──────→[投影]──────────────────→ 状态token ─┘         │
                                                                        ▼
                                                              [动作头 action head]
                                                          (A) 自回归离散 / (B) 连续生成
                                                                        ▼
                                                          a_{1:H} 动作chunk → 机器人执行
```

| 阶段 | 内容 |
|---|---|
| 输入 | 视觉 `o`(多相机)+ 语言 `l` + 本体 `p`(可选) |
| 处理 | 图像/文本各自编码 → VLM 主干跨模态融合 → 动作头 |
| 输出 | 动作 chunk `a_{1:H}`(未来 H 步,不是一步) |
| 训练 | 行为克隆:让预测动作逼近"那个观测下人的动作" |

**理解校准要点**:
- 本体状态"可选"不是因为冗余(图像被遮挡时看不到精确关节角),而是很多模型为简单/统一动作空间选择不用;用上通常有帮助。
- 训练目标不是"像人的风格",而是复现"**看到这个画面→人会做的动作**"这个映射。
- "统一模型吃多模态"是 RT-2 的范式突破。

### 1.2 两种动作头详解

**方法 A:自回归离散(RT-2 / OpenVLA)**
- 动作向量每一维**分箱**(如 256 格)→ 变成整数 → 当"词"塞进 LLM 词表 → **自回归**逐 token 预测 → **交叉熵损失**。
- 优点:复用 LLM 架构与权重,简单,继承语义。
- 缺点:① 量化误差(精度被格子数卡死);② 逐 token 慢;③ 把连续控制当分类,丢几何结构。

**方法 B:连续生成(π0 / Diffusion Policy / Fast-WAM)**
- 不离散化,用**扩散/流匹配**:训练给真实动作加噪→学去噪;推理从纯噪声迭代几步(如10步)去噪出动作 chunk。结构上是接在主干后的"**动作专家**"小网络。**回归损失(MSE/流匹配)**。
- 优点:① 精度高(连续);② 能建模**多峰分布**(同场景多种合理做法);③ 出整段;④ 少步够快。
- 缺点:需迭代几步(但步数少,不是瓶颈)。

> 一句话:离散=把控制当填词游戏借 LLM 的力;连续=从噪声里雕出轨迹,精度和多样性更好。前沿(π0、Fast-WAM)都走连续法。

### 1.3 五个核心概念澄清

**① "不显式建模世界会怎么变"**:模型内部**没有**"执行动作 a→下一刻画面 o' 会怎样"的预测器(=世界模型)。VLA 是**反射式**:看画面→直接吐动作,从不预演后果。→ 不能前瞻规划、不能心里试错。类比:老司机脑中会预演"猛打方向会甩尾",VLA 只有条件反射。

**② web 级预训练**:视觉/语言主干先在**互联网规模图文**(几亿~几十亿)上训过,远超机器人数据(几万~几十万)。好处:模型见机器人数据前**已认识世界**(知道杯子/烤箱/红色);机器人微调只教"怎么动手"。这是 VLA 泛化的主要来源——V/L 来自 web 预训练,A 是微调上去的。

**③ 误差累积 & 为什么 chunking 缓解**:
- **误差累积(compounding error)**:一步一动作→每步小误差→机器人**偏离演示分布**→到陌生状态预测更差→误差滚雪球放大。数学上单步误差 ε 走 T 步可达 **O(ε·T²)**(经典 BC 界,DAgger 动机)。
- **chunking 为何缓解**:① 一次出 H 步连续执行,**重新决策次数↓→误差注入/反馈放大频率↓**;② 段内一起规划,时序连贯;③ 减少高频重规划抖动。
- 折中:chunk 太长闭环性差 → 配合**滚动时域**(出一段只执行前几步再重规划)。

**④ 推理为什么快**(相对 WAM 的 imagine-then-execute):VLA **不生成未来视频**,单次前向或少步去噪即可(~180ms);而 WAM 传统法要**迭代去噪生成高维未来视频**(几千 token×多帧×多步),极慢(580~810ms)。**VLA 快 = 省掉"想象未来画面"这最贵一步。** Fast-WAM 的洞察正是 WAM 也能省掉它。

**⑤ 局限(咖啡豆例子的精确拆分)**:用户例子"柜子里学会拿豆、豆在桌上就失败"其实混着两个相关但不同的局限:
- **泛化/分布偏移(OOD)**:训练分布外就崩。咖啡豆例子属于这个,根源是数据覆盖不足+反射式映射无推理。
- **不建模世界动力学**:不能预演/规划。
- **两者相连(WAM 的假设)**:学"世界如何演化"→更好表征→**既提升泛化又获得前瞻**。Fast-WAM 结论:主要是"**训练期表征提升(泛化)**"在起作用,"测试期预演(规划)"贡献有限。
- "LLM 能讲怎么做咖啡但做不出" 类比准确:VLA 把 LLM 的"知道"(陈述性知识)接上"会做"(运动技能),但运动技能数据稀缺、泛化弱,所以"会做"这部分还很脆。

### 1.4 只靠 data flow 能"完全"理解 VLA 吗?——不能
data flow 是骨架,还差 6 块:① 训练目标/损失(交叉熵 vs 流匹配);② 数据与动作空间(采集/归一化/坐标系/跨本体);③ "为什么这么设计"的动机;④ VLM 预训练的作用(泛化主因);⑤ 评测与失败模式;⑥ co-training/数据配比。
> 理解一个模型 = data flow(骨架)+ 训练目标(灵魂)+ 数据/动作空间(地基)+ 设计动机(为什么)。速成读懂 WAM 够用;做研究/改模型必须补后三块。

## 第 2 部分:WAM 数据流(9 问)

**核心区别一句话**:VLA 是 `o,l → a`;WAM 是 `o,l →(想象未来 v)→ a`,且额外用视频预测目标训练。要分训练/推理两套流程,且**三种范式推理流程不同**。

### 训练数据流(三范式基本一致)
```
o 首帧 ─[VAE]→ 干净首帧latent ┐
v_{1:T} 未来帧(仅训练可见)─[VAE]→ 干净latent ─[加噪]→ 加噪未来latent ┼→[世界模型主干 Video DiT + 动作专家, MoT共享注意力]
l 语言 ─[T5]→ 文本token(cross-attn) ────────────────────────────────┤        │
a_{1:H} 动作 ─[动作编码器]→[加噪]→ 加噪动作token ─────────────────────┘        ▼
                                                            L_vid(预测未来视频)+ L_act(预测动作)
                                                            L = L_act + λ·L_vid
```

**Q1. 我初步掌握 VLA 了吗?能学 WAM 了吗?**
能,已跨门槛。唯一贯穿性小误区:别再把"动作 token"当离散文字命令——换成"**动作是连续向量、和图像 latent 一样能加噪去噪**",WAM 里"一起去噪"就全通了(见 Q8)。

**Q2. WAM 的"首帧"= VLA 第三人称图?为什么只要一帧?**
"帧"是**时间**维度的第一帧(=当前时刻观测),不是"只用一张相机"。当前时刻照样可多相机拼接(Fast-WAM:多相机拼成一张大图再送 VAE)。"只要一帧"是**相对未来帧**说的:推理时你只能观测"现在",未来帧是模型要预测的。**没丢腕部相机。**

**Q3. 未来帧多个,一帧一个 token 吗?为什么加噪?VAE 加的吗?**
- 一帧→**一个 latent 网格(很多 token)**,不是一帧一个 token;视频 VAE 还在时间上压缩。
- **噪声不是 VAE 加的**。VAE 只压缩,出干净 latent;**噪声是流匹配/扩散故意加的**(`y_t=(1-t)y+t·ε`),让模型学去噪。首帧是给定条件保持干净,未来是待生成目标所以加噪。

**Q4. 动作 chunk 哪来?数据集标签?覆盖首帧到未来帧?**
- 来自**数据集真实标签**(遥操作录的),与 VLA 同源(Fast-WAM H=32)。
- **时间上与未来帧对齐**:动作是因、未来画面是果。
- 措辞纠正:训练时动作 chunk 是**被加噪的监督目标**,不是干净输入;干净输入只有首帧+语言。推理无真实动作,从噪声去噪得预测动作。

**Q5. WAM 也像 VLA 共享注意力做融合吗?**
是(MoT+共享注意力),**但多了结构化掩码**:动作 token 能看首帧、**不能看未来视频 token**。是受控融合,不是自由融合。(详见第 3 部分)

**Q6. 未来帧和动作 chunk 都是监督标签吗?**
对,完全正确。`L_vid`(未来视频)+ `L_act`(动作),`L=L_act+λ·L_vid`。都是被加噪再去噪的目标。推理时(Fast-WAM)未来视频分支移除,只输出动作。

**Q7. 范式 A(imagine-then-execute)动作头怎么工作?**
两步:①想象:`o+l →迭代去噪→ 想象未来视频 v̂`;②执行:`o+v̂ →动作模块→ a`。动作头输入=当前观测+**生成的未来视频**,输出=动作 chunk。中间本质是**逆动力学思路**(知道现在和未来,反推中间动作)。慢在第一步生成高维视频(580~810ms)。

**Q8. 范式 B:未来视频 token 和动作 token"一起去噪"?动作不是像文字命令吗?怎么去噪?**
**关键卡点**:连续生成范式里,**动作 token 是连续向量不是离散文字**,所以能像图像 latent 一样加噪去噪(同一套数学)。
- 离散法(RT-2):动作当文字 token,自回归填词,**不去噪**。
- 连续法(π0/Fast-WAM):动作是连续向量,**能去噪**。
- "一起去噪":范式 B(Joint)把未来视频 latent 和动作向量都加噪,**同一模型经共享注意力在同一扩散过程里同时去噪**,共享时间步、互相看着对方去噪,以保持"动作↔它产生的未来"自洽。
- 对比 Fast-WAM(C):推理时**只给动作去噪,完全不碰未来视频**——这是它快的原因。
> 记住:去噪不是图像专利。任何"连续向量+训练时加过噪"的东西都能去噪。动作能否一起去噪,取决于用连续法还是离散法。

**Q9. 范式 C(Fast-WAM)Video DiT 单次前向输入/输出?就是 o,l→主干→a 吗?**
```
o(首帧,VAE干净latent) + l(语言,cross-attn)
      → [Video DiT 单次前向,不生成任何未来视频] → z(o,l) 隐世界表征
      → [动作专家 少步去噪 ~10步] → a 动作chunk
```
- Video DiT 输入=干净首帧+语言,**无加噪未来视频**;输出=`z`。
- **它在这里不生成视频,而是被当"世界编码器"用**——这是 Fast-WAM 最核心一招(把预训练视频模型改造成单次前向编码器)。
- `o,l→主干→a` ✅ 成立;细化:主干出 `z`,动作专家在 `z` 上再去噪出 `a`,全程不生成未来视频 → 既保留 WAM 训练收益又拿到 VLA 速度(190ms)。

### 三范式对比
| | 范式A imagine-then-execute | 范式B Joint | 范式C Fast-WAM |
|---|---|---|---|
| 推理 | 先生成未来视频→再出动作 | 视频+动作一起去噪 | 只编码当前帧→出动作 |
| 是否生成未来视频 | 是 | 是 | **否** |
| 延迟 | 810ms | 580ms | **190ms** |

## 第 3 部分:注意力掩码与信息泄漏

**谁看谁(Fast-WAM 训练掩码):**
| token 组 | 能看 | 不能看 | 角色 |
|---|---|---|---|
| 干净首帧 latent | 只看组内 | 不看未来视频/动作 | 共享锚点(只读的"现在") |
| 未来视频 latent(仅训练) | 首帧+组内彼此 | — | 视频协同训练去噪目标 |
| 动作 token | 首帧+组内彼此 | **❌ 未来视频** | 动作预测去噪目标 |

**为什么禁止动作看未来视频:**
- 训练时模型握着真实未来帧,而**动作是产生未来帧的原因**——未来帧里"藏着动作答案"。
- 若允许动作看未来,模型走**捷径**:不学"从当前+语言推断动作"(推理时唯一能做的),而学"看未来反推动作"(=逆动力学,太容易)。

**泄漏的后果——不是普通过拟合,是"训练/推理错配":**
- 推理时**根本没有未来帧**,依赖它的模型一到推理就**直接崩**(不是精度略降)。
- 术语:**信息泄漏/捷径学习**。比经典过拟合更致命(经典过拟合是新数据泛化变差,这里是学到的能力测试时用不了)。

**为什么首帧"谁也不看":**保证 `z(o,l)` 在**训练和推理时用完全相同方式计算**(推理时只有首帧过 DiT)。若训练时首帧还看未来/动作,则 z 训练/推理不一致。

**掩码干两件事:**① 堵死动作偷看未来的捷径 → 逼学真正的 `o,l→a`;② 让世界表征 z 训练/推理一致。

## 第 4 部分:LAM vs IDM

**根本区别(先厘清概念混淆):**
| | IDM(逆动力学模型) | LAM(潜在动作模型) |
|---|---|---|
| 输入 | (o_t, o_{t+1}) | (o_t, o_{t+1}) |
| 输出 | **真实动作** â_t | **潜在动作** z_t(非真实动作) |
| 要真实动作标签? | **要**(有监督) | **不要**(自监督) |
| 怎么训 | 预测动作 vs 真实动作 | 用 z 重建下一帧(encode 前后帧→z→decoder 从 o_t+z 重建 o_{t+1}),z 压低维被迫只装"变化=动作" |

**为什么有成熟 IDM 还要 LAM:** 因为 **IDM 需要真实动作标签才能训,不能凭空造标签。**
1. **预训练数据没标签**:互联网/人类视频**无动作标注** → IDM 训不起来,只能自监督(LAM)。
2. **跨本体动作空间不统一**:人手 ≠ 夹爪,机器人 A 的 IDM 给人类视频打的标签无意义;LAM 潜在动作学"画面发生什么运动",与本体无关,能跨。

**回答"已有 IDM 不就能获得干净动作标签吗":** IDM 的干净真实动作**只在有真实标签处才有,且只能同本体传播**;要预训练的无标签跨本体大数据那里 IDM 束手无策。代价:LAM 潜在动作 z **不能直接执行**,后面要用少量有标签数据学 `z→真实动作` 解码头(Motus Stage 3 / LAPA)。

**关键推论:用真实动作监督的 LAM = IDM。**
- 用户直觉正确:有真实标签就能训"两帧→动作"encoder,那就是 IDM。Motus 就掺了 **10% 有标签对齐**(90% 自监督+10% 对齐)。
- 坚持无监督潜在动作的唯一理由:**要在没标签、跨本体的大数据上预训练**——那里真实监督不存在。
- **更深一层**:"两帧→动作"encoder(不管吐真实还是潜在动作)只是**离线打标签/预训练工具,不是上线策略**。部署策略是**前向**的(只有当前帧、要决定动作,没有未来帧)。所以"真实 vs 潜在"对部署策略只是训练目标之别;真正分水岭是**能不能在无标签数据上做出这个目标**——LAM 赢在这。

## 第 5 部分:隐世界表征与动作专家

**Q. z(o,l) 是什么?为什么"包含世界会怎么变"?**
- 表面是特征向量,但**关键是谁算的**:经过**视频协同训练的 Video DiT** 主干产出。
- **原理:表征装什么,由训练任务决定。** 训"预测下一帧"→表征**被迫**装进 运动/物理约束/动作如何改变场景(否则预测不准、损失降不下去)。
- **推理只喂一帧怎么还懂演化?** 动力学知识早**焊进权重**了。单帧过带动力学先验的权重,算出的特征本身就"预判性"。类比:物理学家看"球悬空"静图 → 看到"它在下落、会砸到那"。
- **诚实收紧**:z 不是"装着未来画面",而是**携带"倾向于怎么演化"的先验**(dynamics-aware),不是显式未来预测。呼应 Fast-WAM 结论:价值在训练期把表征塑造得懂世界。

**Q. 动作专家是什么?为什么能从 z 得到动作?**
- **动作专家**:独立的较小 Transformer/DiT(Fast-WAM ~1B,隐藏维1024),MoT 里专管动作模态的"专家"。拿 z(经共享注意力)+ 流匹配少步去噪 → 动作 chunk。
- **为什么 z 能出动作**:① z 信息足够(当前场景 o + 语言目标 l + 动力学先验);② 动作专家被 `L_act` 在 **(z, 真实动作)配对**上训过(=行为克隆),学会"这个场景理解 z → 人会做的动作 a"。
- 比喻:z 是"对场景+物理的深度理解";动作专家是"看着这份理解就知道出什么手"的策略头。

## 一页速记
1. **VLA** = `o,l→a`,反射式,靠 web 预训练泛化,action chunking 抗误差累积,快因不生成视频。
2. **两种动作头**:离散(填词,借 LLM)/ 连续(去噪雕轨迹,精度+多峰,前沿主流)。
3. **WAM** 训练时多带未来帧+动作作监督(`L=L_act+λL_vid`);三范式差在推理是否生成未来视频。
4. **动作能去噪**因为它是连续向量;Fast-WAM 推理只给动作去噪、不碰未来视频(190ms)。
5. **掩码**堵死"动作偷看未来"的捷径(否则训练/推理错配崩掉)+ 保 z 训练/推理一致。
6. **LAM vs IDM**:有标签→IDM;无标签跨本体大数据→只能 LAM。真实监督的 LAM=IDM。
7. **z 懂世界**因"预测未来"训练把动力学焊进权重;**动作专家**在 (z,真实动作) 上学会前向策略。
