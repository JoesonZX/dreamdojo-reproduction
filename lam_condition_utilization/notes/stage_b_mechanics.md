# 阶段 B 机制说明(2026-07-21)

解释阶段 B 的实验**怎么设计的、为什么这么设计**——五个臂、两个指标、
三个对照的证伪逻辑、配对挖掘。结果与判定见 `stage_b_plan.md`;
概念背景见 `concepts_and_pipeline.md`。

---

## 1. 五个臂:同底座 + 唯一变量

五个臂**共享完全相同的底座**——同一预训练起点(`LAM_400k.ckpt`)、
KL + L_zero 的 trunk、修正后的 LR 调度、排除同一冻结评测 manifest。
**唯一区别是加了什么额外 loss**,所以任何差异都只能归因于那个 loss。

| 臂 | config | 加了什么 | 回答什么问题 |
|---|---|---|---|
| **B 基线** | `ft_l40_sb_B` | 什么都不加 | 不加任何方向/利用率 loss 时,模型本来是什么样(参照系) |
| **R 匹配对照** | `ft_l40_sb_R` | 对**近正交**运动对施加同样的推远 loss | 收益来自**方向配对**还是**任何排斥都行**?(§3) |
| **D 方法** | `ft_l40_sb_D` | 对**反平行**运动对施加推远 loss(= L_dir 本体) | 方向 loss 有没有用 |
| **U 利用率** | `ft_l40_sb_U` | L_use(逼解码器必须用 z_a,否则重建变差) | 瓶颈是不是解码器不用 z_a |
| **S 哨兵** | `ft_l40_sb_S` | 对**同向**运动对施加推远 loss(仅 300 步) | 保险丝(§3) |

**为什么要 B 和 R 两个对照**:B 回答"D 比什么都不加好吗",R 回答"D 比乱推好吗"。
**R 才是主对照**——任何 loss 只要往 latent 施加压力,几乎都会改变几何、可能碰巧
改善某些指标。只有 D 显著胜过 R,才能说收益**特定来自方向**,而非"施加了压力"
这个泛泛的事实。(顾问反复强调:主对比必须是"方法 vs 匹配对照",不是"方法 vs 零"。)

## 2. 两个指标:信息存不存在 vs 下游用不用

顾问坚持拆开的两个**不同**问题——availability(可得性)与 utilization(可用性)。

### H1 = 信息可读性(representation amplification)
- **问**:z_a 里有没有比对照更多的方向信息,能被读出来?
- **怎么测**:冻结 encoder,训一个小 logistic probe 分相反动作。两种输入——
  baseline `[Z_static, 0]` vs full `[Z_static, Z_trans − Z_static]`。
  full 比 baseline 分得更准 ⇒ 转移 latent 携带了静态帧没有的方向信息。
- **关键量**:`P = full 相对 baseline 的 held-out NLL 增益 − 置换 null`。
  ⚠️ 减 null 是因为 full 多给 32 个含噪特征本身有过拟合红利,无信息基线不是 0。
- 代码 `code/dirprobe.py`;按 episode 分组 CV(verb 是 episode 级标签,随机切分会泄漏)。

### H2 = 解码器利用率(direction-specific decoder utilization,**主 Tier-1 指标**)
- **问**:解码器会不会真的用 z_a 的方向?
- **怎么测**:固定场景 (o_t, z_e),把 z_a 换成**同动作**捐赠者 vs **相反动作**捐赠者,
  各自解码下一帧,比误差。`C = (MSE_opp − MSE_same) / (motion_energy + ε)`。
  C > 0 ⇒ 喂相反动作的 z_a 解出可测的不同未来,方向是"可执行"的。
- 代码 `code/h2_utilization.py`;运动能量归一化防高运动 clip 主导。

**为什么必须两个都测**:H1 是"信息在不在纸上",H2 是"读者读不读这张纸"。
信息可以完美写在 latent 里(H1 高),但解码器完全无视它(H2=0)——这正是我们的观测。
世界模型最终要"听指挥",不是"latent 好看",所以 **H2 才是主指标**。

## 3. 三个对照臂:证伪"任何排斥都行"

L_dir 的本质是"**把某些成对的 z_a 推远**"。危险:推远这个动作本身就会让 latent
空间散开,可能碰巧改善指标——即使推的是**毫无意义**的对。不排除这点,就无法区分
"方向 loss 有效"和"任何排斥都有效"。

三个臂用**完全相同的 loss、完全相同的对数**,只有"推哪些对"不同:

| 臂 | 推的对 | cos 门 | 语义 | 作用 |
|---|---|---|---|---|
| **D 方法** | 反平行 | cos < −0.5 | 伸手 vs 收手(真·相反) | 想验证的 |
| **R 近正交** | 正交 | \|cos\| < 0.2 | 无方向关系 | **主对照**:同样推远预算,施加在无方向关系的对上 |
| **S 同向** | 同向 | cos > +0.5 | 推进 vs 推进(本该相似) | **保险丝**:推开同向对语义上是**错的** |

判读逻辑:
- **D 胜 R** ⇒ 收益特定来自"推反平行对",方向配对有意义 ✓
- **D ≈ R** ⇒ 任何排斥都一样,方向无特殊性 ✗(← 实际结果)
- **S 也"有效"**(推开同向对也改善指标)⇒ **警报**:loss 纯粹是散开正则、与方向无关,
  方向主张当场作废。S 只跑 300 步当保险丝,一旦复制 D 的改善就立即停手。

挖掘时三类一次产出(`data/dir_pairs_train.npz` 的 `kind` 字段 0/1/2),
配对数量、Δt/幅度门完全一致,保证"唯一变量是 cos 门"。

## 4. 怎么在 episode 内挖运动反平行帧对

完全**不解码视频**,只读 HDF5 的手部位姿轨迹(EgoDex 每帧有 leftHand/rightHand 的
4×4 SE(3) 位姿 + camera 位姿)。代码 `code/mine_dir_pairs.py`。

**第 1 步:算每帧对的运动向量。** 每个时刻 t 取移动更多的那只手,算 Δt(1 帧)内位移。
关键做**相机运动补偿**:把世界系位移旋到 t 时刻相机坐标系(`inv(C_t)` 作用在位移上),
得到"去掉自我运动后手相对相机怎么动"。审计测出相机运动残差中位 18%(p75 46%),
不补偿则方向向量被自我运动污染。

**第 2 步:三道门筛配对**(审计逼出来的,缺一不可,详见 `dir_pair_audit.md`):
1. **同 episode**——外观天然共享,模型无法用"这是哪个场景"偷偷区分,只能靠运动方向;
2. **时间窗 Δt ∈ [0.5, 2] 秒**——**最关键也最反直觉**。不加时间窗,"反平行"只比随机
   高 **1.24×**(几乎巧合:3D 随机向量本就 25% 落在 cos<−0.5);而 0.5–2 秒窗口内
   (一次伸手/收手子动作的时长)反平行率是随机的 **2.59×**。窗口外的巧合对会淹没
   窗口内的真信号;
3. **幅度 > episode 内 p80**——滤抖动,只留真正在动的帧对。

**第 3 步:按运动向量余弦分三类**(对应三个臂):
cos<−0.5 反平行(D)/ \|cos\|<0.2 近正交(R)/ cos>+0.5 同向(S)。

**产出**:236,784 反平行对(排除评测 manifest 后),92.5% episode 有配对,107 task 全覆盖。
**训练时** `DirPairDataset` 按 `(video, t, skip)` 直接取那两个帧对
——不能用样本下标,因为 dataset 的 `__getitem__` 里 skip 是随机选的。

⚠️ **诚实边界**:这套挖掘用 **GT 手部位姿(oracle)**,不是真正的 label-free。
它只回答"方向配对机制的**上界**"。论文主线本该换光流/关键点自监督代理——
但既然 oracle 上界都失败,proxy 只会更弱,故此管线止损不做。

## 5. 为什么方向线不成功(三层)

- **Tier-0 机制:成功**。L_dir 把反平行对 z_a 余弦从 +0.16 推到 −0.30,几何被实质改变。
- **Tier-1 外部收益:失败**。H1 的 ΔP(D−R) CI 含 0,H2 的 C 全臂 ≈ 0。
  几何变了,但下游没多知道任何东西、也没多听任何指挥。
- **根因(推测,待验证)**:H2 的 C≈0 是**全臂共性**,不是 D 特有。问题很可能不在
  "L_dir 设计不好",而在 **decoder 本来就不响应 z_a 的方向**——与 lf 塌缩、
  条件 probe 三个独立证据同源,都指向 utilization 而非 availability。
  **在 encoder 侧摆好方向没用,因为 decoder 那端的门是关着的。** 修 encoder 修不好
  decoder 的病。零成本验证方案(评测改用 z_mu 而非采样 latent)见
  `consult_story_b_prompt.md` 末尾问顾问的 #3(b)。
