# exp3（独立性损失）失败分析与改进方案

配套 [`results-v1.md`](results-v1.md)。本文专门分析 exp3 为何失败、修复思路，以及未来方向。

## 1. 现象

exp3 = exp2 + 去相关损失（λ_indep=0.02，无 warmup）。结果动作信息整体崩塌：

| 指标 | exp2 | exp3 | 期望 |
|------|------|------|------|
| 动作子空间 动作回归 R² | 0.133 | **−0.002** | ≥ exp2 |
| 动作子空间 task 分类 | 51.1% | **10.8%** | ≥ exp2 |
| 环境子空间 task 分类 | 19.0% | 5.9% | 越低越好 |
| 重建 PSNR | 29.61 | 30.09 | 持平 |

环境维确实变"更不含动作"了（19%→5.9%），但**代价是动作维也几乎不含动作了**——不是解耦，是整体塌缩。

## 2. 根因诊断（训练日志证据）

| step | exp3 act loss | exp3 indep loss | exp1 act loss(对照) |
|------|------|------|------|
| 100 | 1.19 | **50.2** | 1.14 |
| 2100 | 1.22 | 2.79 | — |
| 10000 | **1.15（几乎没降）** | 1.9 | **0.95（持续在降）** |

- **早期梯度过载**：step 100 时 indep=50，×λ0.02 ≈ 1.0，与动作损失（~1.15）同量级。表征
  刚开始形成时就被一股强去相关梯度主导。
- **动作损失全程不降**：停在 ~1.15（≈"预测均值"，R²≈0），对照 exp1/exp2 降到 0.95。
  说明 encoder 没能在前 32 维学出动作映射 → 冻结后 probe 自然测不到动作信息。
- **去相关的"廉价解"**：最小化动作维/环境维互相关，最省力的方式之一是**压低某子空间的
  有效信息/方差**，而非"各自保留有用且互不相关的信息"。在动作监督还没站稳时，优化器走了
  这条捷径，把动作子空间的结构也抹掉了。

**结论：λ 过大 + 无 warmup + 损失尺度未归一**，三者叠加导致过度正则、表征塌缩。

## 3. 已实施的修复与结果

train.py 新增 `indep_warmup`：λ_indep 在前 N 步从 0 线性升到目标值，让动作子空间先在
动作监督下成形，再逐渐施加去相关压力。两个修复 run（GPU 0/1，各 ~30 分钟）：

| run | λ_indep | indep_warmup | 其余 |
|-----|---------|--------------|------|
| `exp3_fix_a` | 0.005 | 2000 步 | 同 exp2 |
| `exp3_fix_b` | 0.002 | 2000 步 | 同 exp2 |

**成功判据**：动作子空间 R²/task 分类 ≈ 或 > exp2（不塌），同时环境子空间 task 分类
明显 < exp2 的 19%（解耦更彻底）。

**结果（n=4000）**：

| run | 动作子空间 R² | 动作子空间 task | 环境子空间 task | 环境子空间 ep | PSNR | 判定 |
|-----|------|------|------|------|------|------|
| exp2（对照） | 0.133 | 51.1% | 19.0% | 18.4% | 29.61 | 动作强、环境不净 |
| exp3 原版(λ0.02,无wu) | −0.002 | 10.8% | 5.9% | 10.7% | 30.09 | **塌缩** |
| exp3_fix_a(λ0.005,wu2k) | −0.001 | 16.8% | 6.2% | 8.6% | 30.08 | 仍偏塌 |
| **exp3_fix_b(λ0.002,wu2k)** | **0.026** | **29.5%** | **7.5%** | 15.4% | 30.06 | **有效但有代价** |

**解读**：
1. **warmup 诊断被证实**：fix_b 动作 task 从原版 10.8%→**29.5%**（不再塌成 chance），证明
   "早期 indep 梯度过载压塌表征"成立、warmup 有效；λ 越大越塌（fix_a 0.005 仍偏塌）。
2. **环境维更干净**：fix_b 环境 task 仅 **7.5%**（exp2 是 19%）——独立性损失确实把动作信息
   挤出了环境维，这是它的核心价值。
3. **但尚未全胜 exp2，存在权衡**：fix_b 动作 task 29.5% < exp2 的 51%。去相关在清理环境维的
   同时**连带削弱了动作维的动作信息**——它移除的是两子空间间的*共享/相关*成分，而非单纯搬运。
4. **当前最优档 = λ0.002 + warmup2k**；要"环境净 + 动作不掉"两者兼得，需第 4 节的防塌缩约束。

## 4. 进一步改进方向（按优先级）

当前 fix_b 已证明"不塌 + 环境更净"可达，但动作保真度还不及 exp2，根因是去相关会顺带
削弱动作维的*相关*动作成分。下面按"最可能两者兼得"排序：

1. **★ 防塌缩约束（最优先）**：给去相关配一个 **VICReg 方差保持项**
   `mean(relu(1 - std(z)))`，强制每个维度保留方差，杜绝"压低方差作弊降相关"，让 indep
   只去*冗余相关*而非*有用信息*。预期能在 fix_b 基础上把动作 task 拉回接近 exp2。
2. **★ 主动监督环境维**：给 z_e 一个辅助目标（回归 ep/scene 嵌入），把环境信息**主动拉进**
   环境维，而非仅靠去相关被动排斥——通常比纯独立性损失更稳、更不伤动作维。
3. **归一化去相关损失**：当前是 32×8=256 项平方**和**，量级随维度膨胀；改成**均值**
   `(C**2).mean()` 让 λ 更可解释、梯度更稳。
4. **更强独立性度量**：距离相关 dCor（捕捉非线性依赖）；或对抗式（判别器从 z_e 预测 z_a）。
5. **调度**：indep 损失单独梯度裁剪；warmup 拉长到 3–4k；或更低 λ（0.001）再扫一档。
6. **扩大 batch**：去相关是 batch 内统计量，batch 32 估计偏噪；提速后可加大 batch。

## 5. 给报告读者的一句话
exp3 经 warmup+降权后**从"塌缩失败"变为"有效但有代价"**：环境子空间显著更干净（task
19%→7.5%），但动作保真度暂不及 exp2（task 51%→29.5%）。根因是去相关**没有指派方向**、且会让
两子空间的共享信息一起消失。

## 6. 后续：exp4 信息瓶颈是更好的替代（已验证）
基于"去相关不能指派信息归属"的诊断，改用**对 z_a 加更强 KL（信息瓶颈）、z_e 极弱 KL**的方案
（exp4，见 [`results-v1.md`](results-v1.md) §3(4)）。结果：β_a=1e-3 实现**定向提纯**——真实动作
回归 R² 持平/略升（0.133→0.138）的同时，z_a→场景(ep) 47.6%→37.0%。这正是去相关做不到的，
因为 KL 瓶颈"只删动作损失不保护的信息"，天然带方向、且先验方差为 1 不会塌成 0。
**故"主动机制（瓶颈）"优于"被动惩罚（去相关）"。** 独立性损失这条线如仍要走，需配 VICReg
方差保持项（防塌缩）；但目前 exp4 已是更优解。
