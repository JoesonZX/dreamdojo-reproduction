## Q1 — 重建（PSNR）的 tradeoff

把所有 `results/*/recon.txt` 与 `probe*.txt` 汇总（含本次补测的 **raw LAM_400k 0 步锚点**）：

| 轨道 | run | 动作 R² | PSNR (dB) | 说明 |
|---|---|---:|---:|---|
| **官方原始** | LAM_400k（0 步） | 0.127 | **38.29** | 成熟解码器，未注入 EgoDex 动作 |
| 从零 60M/10k | baseline（无动作头） | 0.003 | 30.77 | 重建上限，几乎无动作 |
| | exp1（动作监督, 32） | 0.126 | 29.60 | **−1.2 dB = 注入动作的一次性代价** |
| | exp2（32+8 拆分） | 0.133 | 29.61 | 加环境维 ≈ 免费 |
| | exp4_e（KL 瓶颈） | 0.145 | 29.67 | 解耦最好，重建不动 |
| | exp3（去相关, 失败） | −0.002 | 30.09 | PSNR 反而高 —— 因为把动作丢了 |
| 从零 700M/40k | exp2 | 0.274 | 32.57 | |
| | exp4（β_a=3e-3） | 0.243 | **32.93** | 更解耦**且**重建更高 |
| **微调 LAM_400k** | ft_l32_frozen（1k） | 0.128 | **38.63** | ≈ 未动的官方 LAM |
| | ft_l32_full（1k） | 0.243 | 35.53 | 注入动作 ≈ −3 dB |
| | ft_l32_full_5k | 0.332 | 35.65 | |
| | ft_l40_full（1k） | 0.255 | 32.06 | +环境维（新随机 fc）拉低重建 |
| | **ft_l40_full_5k** ★ | **0.346** | 33.23 | 动作最强，重建回升 |
| | ft_l40_frozen（1k） | 0.113 | 32.09 | |

**结论（要点）**
1. **重建质量由两件事决定**：(a) encoder 离成熟权重被扰动多少；(b) 是否新增 latent 维度
   —— **不是**由 z_a 里装了多少动作决定。
2. **动作↔重建的 tradeoff 是"一次性扰动代价"，不随动作 R² 成比例**：从零 baseline→exp1 掉
   ~1.2 dB；微调 frozen→full 掉 ~3 dB。一旦付过这笔，**继续加解耦（KL 瓶颈）几乎零重建代价**
   —— 700M/40k 上 exp4 的 PSNR 甚至高于 exp2。
3. **PSNR 不是解耦指标**：失败的 exp3、和冻结微调，PSNR 反而**最高**，正因为它们几乎没改动作内容
   （exp3 把动作丢了、frozen 没动 encoder）。所以不能用 PSNR 当作"动作学得好不好"的证据。
4. **微调 LAM 的重建远高于从零**（35–38 vs 30–33 dB），因为继承了官方 400k 步的解码器；
   latent=32（完全复用预训练 fc）> latent=40（新维需重新适配）。
5. **0 步锚点实测 38.29 dB**（本次补测，此前缺失），与 ft_l32_frozen(38.63) 一致 —— 证实
   "冻结微调 ≈ 不动官方 LAM"，也给出官方 LAM 在 EgoDex 上的重建天花板。

## Q2 — 18 维到底是什么"关节"，为何 R² 有大有小

**先纠正一个说法（给导师也讲清楚）**：这 18 维**不是机器人关节**，也**不是 4 维手 + 14 维手腕**。
EgoDex 用 ARKit 记录的是**两只手的 SE(3) 末端位姿（手腕/手根 6 自由度）**。
`dataset.py::_pair_action` 对每只手取相对运动 `T_rel=inv(T_t)·T_{t+skip}`，拆成
`[Δ平移(3) + 6D 旋转(6)]`，左手在前右手在后：

| 维度 | 含义 |
|---|---|
| 0–2 | **左**手 末端 Δ平移（x,y,z，在手自身坐标系） |
| 3–8 | **左**手 6D 旋转（Zhou 2019：旋转矩阵前两列拉平） |
| 9–11 | **右**手 末端 Δ平移 |
| 12–17 | **右**手 6D 旋转 |

也就是 **6 维平移 + 12 维旋转**（不是 4+14）。EgoDex 的 HDF5 其实**有手指关节**的 transform，
但本实验只读 `transforms/leftHand` / `rightHand`（手腕根），**手指关节被刻意排除**。
所以："没有单独对应关节"——对手指是的；但每一维仍对应一个具体量：平移维 = 某只手腕沿 x/y/z 的位移；
旋转 6 维 = 手腕朝向的连续参数化（不一一对应 roll/pitch/yaw，这也是末维 R² 低的原因）。

**逐维 R²（exp2_700m_40k, action-sub，最充分训练的判定 run）**
- 左手 Δ平移 `[0.540, 0.313, 0.324]`
- 左手 6D 旋转 `[0.251, 0.133, 0.125, 0.133, 0.228, 0.074]`
- 右手 Δ平移 `[0.472, 0.545, 0.278]`
- 右手 6D 旋转 `[0.322, 0.365, 0.139, 0.365, 0.245, 0.077]`

**为何有大有小（四条规律）**
1. **平移 ≫ 旋转**（右手 0.43 vs 0.25；左手 0.39 vs 0.16）：6D 旋转在 SO(3) 非线性流形上，
   线性 Ridge 探针本就难拟合；相邻帧朝向变化小且噪声大。**整体 R² 偏低主要被旋转拖累，不代表
   动作没学到。**
2. **右手 ≫ 左手**：EgoDex 操作以右手为主，右手运动幅度大、更可学；左手常静止/辅助（方差低→R² 低）。
3. **平移第 3 维（z/深度）最低**（左 0.324、右 0.278）：前向/深度方向的运动最难从第一视角的近似单目
   视频里恢复（深度歧义）。
4. **6D 旋转最后一维最低**（~0.074–0.077）：6D 表示经 Gram-Schmidt 正交化后，末列最受约束/最冗余，
   对应最不可观测（roll 类）旋转。

## Q3 — 导师的意见对：KL 不是"分离器"，改用对比解耦（ConLA）

**为何 KL 用错了**：exp4 把 KL 做成**非对称瓶颈**（z_a 强 β、z_e 弱 β），想把场景信息"挤出" z_a。
但 KL 只把每一维的边缘分布拉向先验 N(0,1)，是**容量压缩**而非**内容路由**：它从不告诉模型
"动作放这边、场景放那边"，只是缩小 z_a 的总信息量、指望动作监督把动作守住。导师的批评——
"KL 是约束分布的，不该拿来区分动作维/环境维"——成立。

**ConLA（arXiv:2602.00557）的思路**：把 latent 对半分成动作半 z_a / 视觉半 z_v，用**直接的对比
信号**而非 KL 来分离：
1. **动作中心的有监督对比（SupCon）on z_a**：用动作类别标签，把同类动作的 z_a 拉近、异类推远
   （弱监督）。强迫 z_a **跨场景**地按动作语义聚类。
2. **视觉中心 InfoNCE on z_v**：把外观信息路由进视觉半。
3. **时间反转线索（关键无监督信号）**：喂时间反转的帧对 `[O_{t+k}, O_t]` —— 运动反向（z_a 应变化）
   但外观稳定（z_v 应不变），以此直接分离 motion vs appearance。
4. 重建保留，但被对比目标"引导"，避免 shortcut。（它用 VQ-VAE 离散码本；我们是连续 VAE，只借损失思想。）

**本仓库的落地（仅微调，不从头训练）**——已实现：
- 保留 重建 MSE **和** 动作回归头 + MSE（这是 R² 探针的锚，让 z_a 能解码出 18 维真实动作）。
- **把"分离机制"从 KL 瓶颈换成两个 ConLA 信号**（`model.py` 加投影头，`train.py` 加损失）：
  - `lambda_supcon`：z_a 上的 SupCon，用 **batch 内 task_id** 作动作类别先验
    （等价于"把同动作不同 episode 的 z_a 拉到一起"——正好对应下面的聚类指标）。
  - `lambda_temporal`：再编码时间反转对，**z_e 不变性**（拉近）+ **z_a 敏感性**
    （`relu(cos(z_a, z_a_rev))`，正相关才惩罚，避免塌缩）。
  - KL 降为普通 `beta=1e-6`（全维），不再做分离。
- **配置**：`config/ft_l40_contrastive.yaml`（1k 步）与 `ft_l40_contrastive_5k.yaml`（5k 步），
  均从官方 `LAM_400k.ckpt` 全微调，对照 `ft_l40_full`(1k)/`ft_l40_full_5k`(5k)，**仅分离机制不同**。
- ⚠️ 限制：batch=16、111 个 task，单 batch 内同 task 正样本平均仅 ~1 对，SupCon 信号偏弱；
  **temporal 项不需要标签、每个 batch 都有效**，是稳定的主力。后续可用类平衡采样增强 SupCon。

## 新增评估指标 —— 同动作跨 episode 的聚类距离（`eval.py --mode cluster`）

导师/你提的"同动作不同 episode vs 同动作同 episode 的聚类远近"**此前没做过**——原来的 t-SNE
只是定性散点（按 task/ep 上色），没有量化。新模式在 **z_a**（动作子空间，余弦距离、单位归一）上算三池均值：
- `d_ss` = 同动作同 episode；`d_sd` = 同动作不同 episode；`d_dd` = 不同动作。
- **场景不变性 gap = d_sd − d_ss**（→0 表示 z_a 不在意是哪个 episode/场景，即解耦好；<0 更佳）。
- **分离比 = d_dd / d_sd**（↑ 表示不同动作分得开）。
- 另报 z_a 上 task 标签的 silhouette。

**0 步锚点 raw LAM_400k 实测**：gap **+0.0491**、分离比 **1.043**、silhouette **−0.257**
（动作结构很弱、且明显被 episode/场景牵引——正是要改善的起点）。其余 KL 基线（exp4_700m_40k、
ft_l40_full_5k）与新对比 run 的 cluster 结果待回填，与 PSNR/R²/泄漏一并对比。

## 结果：以 raw LAM_400k 为基线，KL vs 对比 v1 vs 对比 v2（微调，已跑完）

> 全部对比 run = 全微调官方 LAM_400k，latent 40(32+8)，有效 batch 16。
> v1：随机采样，beta 1e-6，无 warmup。v2：PK 类平衡采样(P2×K4) + beta 1e-4 + 对比 warmup。
> KL 列取自 [`results-v2-finetune.md`](results-v2-finetune.md)。↓=越低越好，↑=越高越好。

**5k 步（主对比）**

| 指标 | **raw LAM_400k（基线,0步）** | KL `ft_l40_full_5k` | 对比 **v1** | 对比 **v2**(PK) |
|---|---:|---:|---:|---:|
| 动作 R²（z_a→真实动作） | 0.127 | **0.346** | 0.291 | 0.280 |
| 重建 PSNR (dB) | 38.29 | 33.23 | **34.62** | 33.58 |
| z_a→task% | 12.9 | 21.1 | 23.2 | **60.0** |
| z_a→ep%（场景泄漏 ↓） | 13.6 | 18.3 | 20.8 | 53.9 |
| env→task% | — | 6.8 | 13.1 | 25.8 |
| **cluster 场景不变性 gap ↓** | +0.0491 | +0.0298 | **+0.0159** | +0.0426 |
| **cluster 分离比 ↑** | 1.043 | 1.063 | 1.101 | **1.278** |
| **cluster silhouette ↑** | −0.257 | −0.415 | −0.250 | **−0.092** |

### v3 = 用 **verb（场景无关动作标签）** 做 SupCon，并用 **verb 版聚类指标**重测全部

v3 动机：EgoDex 的 task≈场景，v2 的 task-SupCon 把场景拉回 z_a。改用 **performed verb**
（`llm_verbs` + `which_llm_description` 解析出单一执行动词，2861/3243 集可用，85 类，跨多场景/task）
做 SupCon 正样本 → 同 verb 正样本天然跨场景。同时**修正聚类指标**：原来用 task 当"动作"会把
同 task 内不同 verb（如 add_remove_lid 的 add vs remove）错判为"同动作"，因此新增 **verb 版**
（faithful "同动作"）与 task 版并列。

**5k 步全表（KL 为主对照；cluster 分 task/verb 两套，↓=越低越好，↑=越高越好）**

| 指标 | raw LAM_400k(基线) | **KL `ft_l40_full_5k`** | 对比 v1 | 对比 v2(task) | 对比 v3(verb) |
|---|---:|---:|---:|---:|---:|
| 动作 R²（z_a→真实动作） | 0.127 | **0.346** | 0.291 | 0.280 | 0.281 |
| 重建 PSNR (dB) | 38.29 | 33.23 | **34.62** | 33.58 | 33.54 |
| z_a→task% | 12.9 | 21.1 | 23.2 | 60.0 | 51.1 |
| z_a→ep%（场景泄漏↓） | 13.6 | 18.3 | 20.8 | 53.9 | 48.7 |
| z_a→verb%（动作可分↑） | — | — | — | — | **45.6** |
| **cluster gap（task）↓** | 0.049 | 0.030 | **0.016** | 0.043 | 0.074 |
| **cluster gap（verb）↓** | **0.045** | 0.051 | 0.050 | 0.135 | 0.088 |
| cluster 分离比（verb）↑ | 1.053 | 1.037 | 1.042 | 1.067 | **1.156** |
| cluster silhouette（verb）↑ | −0.244 | −0.393 | −0.238 | −0.155 | **−0.106** |

**关键判定（用 verb 版指标后，结论更诚实、也更清楚）**
1. **"同动作可分性"上 verb-SupCon（v3）确实最好**：verb 分离比 **1.156**、silhouette **−0.106**，
   远超 KL（1.037 / −0.393）——**z_a 按动作动词聚得最开、最紧**。这正是"用对比按动作聚类"的成功。
2. **但"场景不变性 gap"上没有任何对比法胜过 raw/KL**：verb-gap raw 0.045 ≈ KL 0.051 ≈ v1 0.050
   < v3 0.088 < v2 0.135。原因：SupCon 把 z_a 压成更紧的角度锥，**同时**把每个 episode 的子簇也压得
   更紧（d_ss 比 d_sd 掉得更快），于是"同动作跨 episode vs 同 episode"的差反而拉大。
   → 换 verb 标签**解决了"按 task≈场景聚类"的问题**（v3 verb-gap 0.088 < v2 的 0.135），但**没消除**
   SupCon 本身带来的 per-episode 收紧效应。
3. **动作 R² 三个对比版都 ~0.28–0.29 < KL 0.346**：SupCon 的分类式角度几何与"连续 18 维线性回归"
   存在张力；换 verb 也没改善 R²。
4. **重建：对比法（尤其 v1 34.6dB）仍略优于 KL（33.2dB）**。

**结论（与 5k KL 的最终对比）**
- **要"动作可分/按动作聚类" → 对比 v3（verb-SupCon）最好**（分离比 1.156、silhouette −0.106，且 R²、
  PSNR 与 KL 相当）。**这是导师"用对比而非 KL 做解耦"方向下、目前最能体现动作结构的 encoder。**
- **要"线性动作保真 R²" → KL `ft_l40_full_5k`（0.346）仍最强**，对比法都在 0.28–0.29。
- **要"场景不变性（同动作跨场景距离最近）" → raw/KL/v1 最好（gap≈0.05）**，SupCon 反而使其变差。
- **一句话**：verb 标签修好了 v2"把 task≈场景拉回来"的错误、并让 z_a 的**动作聚类**明显领先 KL；
  但**线性动作 R² 与场景不变性 gap 两项，KL 5k 仍不输甚至更好**。三者是不同目标，需按下游用途取舍，
  最终以世界模型 Eval#3 裁决。

**可选下一步**：temporal-only（去 SupCon）验证场景不变性上限；或在 SupCon 里对 same-episode 对
降权/设为负，专门消除 per-episode 收紧、把 verb-gap 压下去。
